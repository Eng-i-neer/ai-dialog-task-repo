## 阶段一：手机端 UI 适配（Step 1~5）

> **目标**：侧边栏在手机上变成底部 Tab 栏，所有页面在窄屏下正常显示。  
> **策略**：纯 CSS 媒体查询 + 少量 JS 控制，不改动页面逻辑。

### Step 1：CSS 响应式 — 侧边栏 → 底部 Tab 栏

- **目标**：屏幕宽度 ≤768px 时，侧边栏隐藏，底部显示固定 Tab 导航
- **修改文件**：`frontend/css/style.css`
- **要点**：
  - 新增 `@media (max-width: 768px)` 媒体查询
  - `.sidebar` → `position:fixed; bottom:0; width:100%; height:60px; flex-direction:row;`
  - 隐藏 `.logo-text`、`.nav-text`，只显示 icon
  - `.main-area` → `margin-left:0; margin-bottom:60px;`（给底部 Tab 留空间）
  - `.topbar` → `padding: 0 16px;`，标题字号缩小
  - `.page-content` → `padding: 16px;`
  - 处理已有的 `@media (max-width: 1200px)` 不冲突
- **验证**：Chrome DevTools 切换到手机视图，侧边栏变底部 Tab

---

### Step 2：CSS 响应式 — 各组件手机适配

- **目标**：统计卡片、表单、时间线等组件在手机上正常显示
- **修改文件**：`frontend/css/components.css`
- **要点**：
  - `.stat-grid` → 手机上 `grid-template-columns: repeat(2, 1fr)` 或 `1fr`

  - `.time-picker-group` → `flex-wrap: wrap; gap: 6px;`
  - `.timeline-actions` → 手机上始终可见（无 hover）
  - `.photo-upload-area` → 全宽
  - 日期选择器 `.date-picker` → 适配窄屏
  - 表格 `.table` → 横向滚动 `overflow-x: auto`
- **验证**：各页面在 375px 宽度下内容不溢出、不重叠

### Step 4：设置页 — 添加「显示模式」切换

- **目标**：在设置页增加手动切换「桌面版/手机版」的选项
- **修改文件**：`frontend/js/pages/settings.js`、`frontend/css/style.css`

  - 设置页新增「显示模式」区域，三个选项：`自动（跟随屏幕）`、`桌面版`、`手机版`

  - 页面加载时从 `localStorage` 读取并应用
- **验证**：切换显示模式后布局立即变化

## 阶段二：用户系统 — 后端（Step 6~10）

> **目标**：支持用户注册、登录、数据隔离。  
> **策略**：JWT Token 认证，所有数据表加 `user_id` 外键。

### Step 6：数据库 — 新增 `users` 表 + 数据表加 `user_id`

- **目标**：创建用户表，给所有数据表添加 `user_id` 列
- **修改文件**：`backend/init_db.py`
- **要点**：
  - 新增 `users` 表：
    ```sql
    CREATE TABLE IF NOT EXISTS users (
        id           INTEGER PRIMARY KEY AUTOINCREMENT,
        username     TEXT    NOT NULL UNIQUE,
        password_hash TEXT   NOT NULL,
        nickname     TEXT,
        created_at   TEXT    DEFAULT (datetime('now','localtime')),
        last_login   TEXT
    )
    ```
  - 给以下表添加 `user_id` 列（ALTER TABLE，默认值 1）：
    - `weight_records`
    - `meal_records`
    - `exercise_records`
    - `ai_analysis`
    - `daily_summary`
  - `user_settings` 改为按 `user_id` 区分（去掉 `id CHECK(id=1)`）
  - 添加索引：`idx_xxx_user_id`
  - **注意**：必须兼容已有数据（ALTER TABLE ADD COLUMN ... DEFAULT 1）
- **验证**：运行迁移脚本，已有数据保留，新列填充为 1

---

### Step 7：后端 — 用户认证模块 `backend/routes/auth.py`

- **目标**：提供注册、登录、Token 验证 API
- **新建文件**：`backend/routes/auth.py`
- **依赖**：需要安装 `PyJWT`（加入 requirements.txt）
- **要点**：
  - `POST /api/auth/register` — 注册（username, password, nickname）
    - 密码用 `hashlib.sha256` 加盐哈希（不装 bcrypt，保持轻量）
    - 用户名唯一性检查
    - 注册成功自动创建 `user_settings` 默认行
  - `POST /api/auth/login` — 登录
    - 验证用户名+密码
    - 返回 JWT Token（有效期 7 天）
    - 更新 `last_login`
  - `GET /api/auth/me` — 获取当前用户信息（需 Token）
  - 中间件函数 `login_required` 装饰器：
    - 从 `Authorization: Bearer <token>` 提取 Token
    - 验证 Token 有效性
    - 将 `user_id` 注入 `g.user_id`
  - JWT 密钥：首次启动时随机生成，保存到数据库 `system_config` 表
- **验证**：Postman 测试注册→登录→获取用户信息

---

### Step 8：后端 — 所有现有路由添加 `user_id` 过滤

- **目标**：所有数据操作按登录用户隔离
- **修改文件**：所有 `backend/routes/*.py`
- **要点**：
  - 所有路由加 `@login_required` 装饰器
  - `INSERT` 语句加 `user_id=g.user_id`
  - `SELECT/UPDATE/DELETE` 语句加 `WHERE user_id=g.user_id`
  - 具体文件清单：
    - `weight.py`：体重增删改查 + 每日汇总
    - `meal.py`：饮食增删改查
    - `exercise.py`：运动增删改查
    - `dashboard.py`：仪表盘数据
    - `ai_analysis.py`：AI 分析
    - `settings.py`：用户设置（改为按 user_id 查找）
    - `upload.py`：文件上传（目录按 user_id 隔离）
    - `ai_vision.py`：AI 视觉（获取设置时按 user_id）
  - **特殊考虑**：`/api/health` 不需要登录
- **验证**：用不同用户 Token 访问 API，数据互不可见

---

### Step 9：后端 — `user_settings` 改造

- **目标**：设置表从单行改为按用户
- **修改文件**：`backend/routes/settings.py`、`backend/init_db.py`
- **要点**：
  - `user_settings` 删除 `id CHECK(id=1)` 约束
  - 新增 `user_id` 列（UNIQUE 约束）
  - 注册时自动插入默认设置行
  - `GET /api/settings` → `WHERE user_id=g.user_id`
  - `PUT /api/settings` → `WHERE user_id=g.user_id`
  - AI API Key 等敏感数据按用户存储
- **验证**：不同用户有独立的设置

---

### Step 10：后端 — 注册 auth 蓝图 + 全面测试

- **目标**：整合所有后端改动
- **修改文件**：`backend/app.py`、`requirements.txt`
- **要点**：
  - `app.py` 注册 `auth_bp`
  - `requirements.txt` 增加 `PyJWT>=2.8.0`

    4. 验证未登录访问 API 返回 401
- **验证**：所有 API 认证和数据隔离正常

## 阶段四：数据迁移 + 上线（Step 15~16）

### Step 15：数据迁移脚本 — 平滑过渡

- **目标**：已有数据无损迁移到新用户系统
- **新建文件**：`scripts/migrate_to_users.py`
- **要点**：
  - 脚本流程：
    1. 自动创建 `users` 表（如果不存在）
    2. 为已有数据创建一个默认用户（如 `admin`，密码 `admin123`）
    3. 所有现有表 `ALTER TABLE ADD COLUMN user_id INTEGER DEFAULT 1`
    4. 将所有已有数据的 `user_id` 设为 1（默认用户）
    5. `user_settings` 原有行关联到默认用户
    6. 输出迁移报告
  - **安全措施**：
    - 迁移前自动备份数据库
    - 迁移日志记录到文件
    - 可重复执行（已迁移的不重复操作）
  - 同时更新 `init_db.py`，新数据库直接创建带 `user_id` 的表
- **验证**：迁移后以 admin 登录，看到所有历史数据

## 风险与注意事项

| 风险 | 等级 | 对策 |
|------|------|------|
| 数据迁移丢失 | 🔴 高 | 迁移前自动备份，可回滚 |
| JWT 密钥泄露 | 🟡 中 | 密钥存数据库，不写代码里 |
| Token 过期体验差 | 🟢 低 | 7天有效期 + 自动跳转登录 |
| 手机 CSS 兼容性 | 🟢 低 | 用标准媒体查询，不用新特性 |  
| 多用户并发写 SQLite | 🟢 低 | 1-3人规模，WAL模式足够 |
