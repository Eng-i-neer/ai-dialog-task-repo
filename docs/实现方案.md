# 🏋️ 减肥日志系统 — 实现方案

> **版本**：V1.1 方案设计（根据反馈修订）  
> **日期**：2026-03-05  
> **定位**：个人定制的体重追踪 + AI 减肥分析系统

---

## 一、需求分析

### 1.1 核心功能

| # | 功能 | 描述 | 优先级 |
|---|------|------|--------|
| 1 | **体重录入** | 随时记录体重（精确到 0.1kg），支持备注（起床、午饭后、晚饭前、睡前、上厕所前后等） | P0 |
| 2 | **时间戳自动记录** | 每次录入自动保存精确时间（到分钟），作为分析维度 | P0 |
| 3 | **当日体重波动图** | 仪表盘展示今日所有体重记录的折线图，横轴为时间，纵轴为体重 | P0 |
| 4 | **多周期体重趋势图** | 曲线图展示体重变动，支持自由选择周期（7天/14天/30天/全程等） | P0 |
| 5 | **AI 智能分析** | 接入 LLM 大模型，分析当日体重状态、饮食策略、运动建议、预计减重量、明日晨起预测体重 | P0 |
| 6 | **饮食记录** | 记录每餐饮食内容（早/午/晚/加餐），可选记录热量 | P1 |
| 7 | **运动记录** | 记录运动类型、时长、消耗热量 | P1 |
| 8 | **数据统计仪表盘** | 综合展示核心指标：当前体重、目标体重、BMI、已减重量、减重速率等 | P0 |

### 1.2 用户画像

- **单用户系统**：专为你个人定制，无需用户注册/登录体系
- **使用场景**：纯本地部署，电脑浏览器查看（桌面端优先设计）
- **录入频率**：每天 3~6 次体重 + 每餐饮食 + 运动记录
- **分析频率**：一天内可随时多次触发 AI 分析，所有分析报告保留在页面展示

### 1.3 非功能需求

| 维度 | 要求 |
|------|------|
| **响应速度** | 页面加载 < 500ms，录入提交 < 200ms |
| **桌面端体验** | 桌面端优先设计，充分利用宽屏布局 |
| **数据安全** | 本地 SQLite，数据不出本机，不上云 |
| **离线容忍** | 纯本地部署，不依赖外网（AI 分析和多模态图片分析除外） |

## 二、技术栈选型

> 基于「加油站系统」已验证的技术体系，进行复用 + 定制适配。

| 层级 | 技术选型 | 说明 | 复用来源 |
|------|----------|------|----------|
| **前端 UI** | 原生 HTML + CSS + JS（SPA） | 零框架依赖，hash 路由 | ✅ 直接复用 `app.js` 路由框架 |
| **后端 API** | Python Flask + Blueprint | RESTful JSON API | ✅ 直接复用架构 |
| **数据库** | SQLite（WAL 模式） | 单文件 + PRAGMA 调优 | ✅ 直接复用 `db.py` |
| **WSGI 服务器** | Waitress | 生产级本地服务 | ✅ 直接复用 |
| **图表** | Chart.js 4.x (CDN) | 折线图、曲线图 | ✅ 直接复用 |
| **AI 文本分析** | DeepSeek / Doubao（可切换） | LLM 智能分析 | 🆕 新增 |
| **AI 图片分析** | 多模态 AI（Doubao Vision 等） | 食物照片 → 热量分析 | 🆕 新增 |
| **字体** | Google Fonts: Patrick Hand | 手写记事本风格（与加油站系统一致） | ✅ 直接复用 |

### 为什么不换框架？

- 加油站系统已验证这套纯原生栈的**性能极限**（骨架屏、Promise.all 并行、聚合 API）
- 本项目功能规模适中（~5 个页面），无需引入 React/Vue 的编译负担
- 可直接复用 `api.js`（零修改）、`utils.js`（零修改）、`app.js`（改页面注册表）

## 四、数据库设计 ⭐

### 4.1 SQLite 配置（直接复用）

```python
# 黄金 PRAGMA 组合 — 直接从加油站系统复用
PRAGMA journal_mode = WAL        # 读写并发
PRAGMA synchronous = NORMAL      # 安全且快速
PRAGMA cache_size = -8000        # 8MB 缓存
PRAGMA mmap_size = 33554432      # 32MB 内存映射
PRAGMA temp_store = MEMORY       # 临时表存内存
```

### 4.2 表结构设计

> 共 **6 张表**，覆盖体重、饮食、运动、AI 分析和系统配置。

---

#### 表 1：`weight_records` — 体重记录（核心表）

> 高频写入、高频查询，是整个系统的数据基础。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| `weight` | REAL | NOT NULL | 体重（kg），精确到 0.1 |
| `recorded_at` | TEXT | NOT NULL | 记录时间，ISO 格式 `YYYY-MM-DD HH:MM:SS` |
| `date` | TEXT | NOT NULL | 记录日期 `YYYY-MM-DD`（冗余字段，索引查询用） |
| `time_of_day` | TEXT | NOT NULL | 时段标签，可选值见下方枚举 |
| `note` | TEXT | | 备注（如「大量喝水后」「运动后」等） |
| `created_at` | TEXT | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**`time_of_day` 枚举值**：

| 值 | 含义 | 典型场景 |
|----|------|----------|
| `morning` | 晨起 | 起床后、上厕所后空腹称重 |
| `pre_lunch` | 午饭前 | 上午活动后 |
| `post_lunch` | 午饭后 | 午餐后称重 |
| `pre_dinner` | 晚饭前 | 下午活动后 |
| `post_dinner` | 晚饭后 | 晚餐后称重 |
| `bedtime` | 睡前 | 一天最后一次 |
| `pre_toilet` | 上厕所前 | 对比排泄影响 |
| `post_toilet` | 上厕所后 | 对比排泄影响 |
| `exercise` | 运动后 | 运动前后对比 |
| `other` | 其他 | 任意时刻 |

**索引**：

```sql
CREATE INDEX idx_weight_date ON weight_records(date);
CREATE INDEX idx_weight_date_time ON weight_records(date, time_of_day);
CREATE INDEX idx_weight_recorded_at ON weight_records(recorded_at);
```

**设计决策**：
- `date` 字段虽然可以从 `recorded_at` 截取，但作为**冗余索引字段**可以显著提升按日查询的性能（避免 `substr()` 函数无法命中索引）
- `time_of_day` 用枚举值而非自由文本，便于后续分析和图表分组
- 保留 `note` 自由文本字段满足灵活备注需求

---

#### 表 2：`meal_records` — 饮食记录

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| `date` | TEXT | NOT NULL | 日期 `YYYY-MM-DD` |
| `meal_type` | TEXT | NOT NULL | 餐次：`breakfast` / `lunch` / `dinner` / `snack` |
| `description` | TEXT | NOT NULL | 饮食内容描述（自由文本） |
| `calories` | INTEGER | | 估算热量（kcal），可选填 |
| `photo_path` | TEXT | | 食物照片存储路径 |
| `ai_calorie_estimate` | INTEGER | | 多模态 AI 根据照片估算的热量（kcal） |
| `recorded_at` | TEXT | NOT NULL | 记录时间 |
| `created_at` | TEXT | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**索引**：

```sql
CREATE INDEX idx_meal_date ON meal_records(date);
CREATE INDEX idx_meal_date_type ON meal_records(date, meal_type);
```

**设计决策**：
- `description` 采用自由文本而非结构化食物数据库，降低录入门槛（AI 会帮你估算热量）
- `calories` 为手动填写的热量，`ai_calorie_estimate` 为多模态 AI 根据照片自动估算的热量（两者共存，优先使用 AI 估算值）
- `photo_path` 存储上传食物照片的相对路径，照片保存在 `backend/uploads/meals/` 目录

---

#### 表 3：`exercise_records` — 运动记录

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| `date` | TEXT | NOT NULL | 日期 `YYYY-MM-DD` |
| `exercise_type` | TEXT | NOT NULL | 运动类型（自由文本：跑步、游泳、力量训练等） |
| `duration_minutes` | INTEGER | | 时长（分钟） |
| `calories_burned` | INTEGER | | 消耗热量（kcal），可选 |
| `intensity` | TEXT | DEFAULT 'medium' | 强度：`low` / `medium` / `high` |
| `note` | TEXT | | 备注 |
| `recorded_at` | TEXT | NOT NULL | 记录时间 |
| `created_at` | TEXT | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**索引**：

```sql
CREATE INDEX idx_exercise_date ON exercise_records(date);
```

---

#### 表 4：`ai_analysis` — AI 分析报告

> 一天内可随时生成多份 AI 分析，全部保留并展示在页面上。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| `date` | TEXT | NOT NULL | 分析日期（同一天可有多条） |
| `analysis_text` | TEXT | NOT NULL | AI 分析全文（Markdown 格式） |
| `weight_status` | TEXT | | 当日体重状态摘要 |
| `diet_advice` | TEXT | | 饮食策略建议 |
| `exercise_advice` | TEXT | | 运动量建议 |
| `predicted_loss` | REAL | | AI 预计今日减重量（kg） |
| `predicted_morning` | REAL | | AI 预计明日晨起体重（kg） |
| `model_used` | TEXT | | 使用的模型名称 |
| `tokens_used` | INTEGER | | 消耗 token 数 |
| `created_at` | TEXT | DEFAULT CURRENT_TIMESTAMP | 生成时间 |

**索引**：

```sql
CREATE INDEX idx_analysis_date ON ai_analysis(date);
CREATE INDEX idx_analysis_created ON ai_analysis(created_at);
```

**设计决策**：
- **不再有 UNIQUE(date) 约束** — 一天内可多次生成分析，每次生成都作为独立记录保留
- `analysis_text` 存完整 Markdown，前端直接渲染
- 结构化字段（`weight_status`、`diet_advice` 等）从 AI 返回的 JSON 中提取，便于仪表盘卡片展示
- `predicted_loss` 和 `predicted_morning` 单独提取，可用于趋势图中的「AI 预测线」
- 新增 `idx_analysis_created` 索引，便于按时间倒序展示当日所有分析
- 前端 AI 分析页面展示当日所有分析报告（最新在上），形成「分析时间线」

---

#### 表 5：`daily_summary` — 每日汇总（聚合缓存）

> 存储每天的关键聚合指标，避免每次查看仪表盘都重新计算。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| `date` | TEXT | NOT NULL UNIQUE | 日期 |
| `morning_weight` | REAL | | 晨起体重（第一条 `morning` 记录） |
| `lowest_weight` | REAL | | 当日最低体重 |
| `highest_weight` | REAL | | 当日最高体重 |
| `avg_weight` | REAL | | 当日平均体重 |
| `weight_count` | INTEGER | DEFAULT 0 | 当日称重次数 |
| `total_calories_in` | INTEGER | | 当日总摄入热量 |
| `total_calories_out` | INTEGER | | 当日总消耗热量（运动） |
| `weight_change` | REAL | | 较前日晨起体重变化（kg） |
| `updated_at` | TEXT | DEFAULT CURRENT_TIMESTAMP | 最后更新时间 |

**索引**：

```sql
CREATE UNIQUE INDEX idx_summary_date ON daily_summary(date);
```

**设计决策**：
- 这是一张**聚合缓存表**，类似加油站系统的 `daily_report`
- 每次录入体重/饮食/运动后，触发**自愈式更新**：从原始数据重新计算并写入
- 7 日趋势图直接查这张表，一次查询拿到 7 天数据，极快

---

#### 表 6：`user_settings` — 用户设置（单行表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY DEFAULT 1 CHECK(id = 1) | 强制单行 |
| `target_weight` | REAL | | 目标体重（kg） |
| `height_cm` | REAL | | 身高（cm），用于计算 BMI |
| `gender` | TEXT | DEFAULT 'male' | 性别 `male` / `female` |
| `birth_date` | TEXT | | 出生日期（计算年龄） |
| `activity_level` | TEXT | DEFAULT 'moderate' | 活动水平：`sedentary` / `light` / `moderate` / `active` |
| `ai_api_key` | TEXT | | AI 文本分析模型 API Key |
| `ai_api_url` | TEXT | | AI 文本分析模型 API URL |
| `ai_model` | TEXT | DEFAULT 'deepseek-chat' | AI 文本分析模型名称 |
| `vision_api_key` | TEXT | | 多模态 AI API Key（图片分析用） |
| `vision_api_url` | TEXT | | 多模态 AI API URL |
| `vision_model` | TEXT | DEFAULT 'doubao-vision' | 多模态 AI 模型名称 |
| `created_at` | TEXT | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | TEXT | DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**设计决策**：
- `CHECK(id = 1)` 强制只存一行，单用户系统最简方案
- AI 配置存数据库而非配置文件，方便前端设置页面修改
- **分离文本 AI 和多模态 AI 配置** — 文本分析可用 DeepSeek/Doubao，图片分析可用 Doubao Vision 等多模态模型
- `height_cm` + `target_weight` 用于计算 BMI 和减重进度

## 五、后端 API 设计

### 5.1 Blueprint 模块划分

```
backend/routes/
├── weight.py          # 体重记录 CRUD
```

## 六、AI 智能分析系统

### 6.1 架构设计

#### 6.1.1 文本分析流程

```
用户点击「AI 分析」（可一天内多次触发）
      │
      ▼
前端 POST /api/ai/analyze
      │
      ▼
后端收集当日数据
├── 今日所有体重记录 (weight_records)
├── 今日饮食记录 (meal_records)
├── 今日运动记录 (exercise_records)
├── 近7日 daily_summary (趋势数据)
├── 用户设置 (身高、目标体重、活动水平)
      │
      ▼
组装 System Prompt + User Prompt
      │
      ▼
调用文本 AI（DeepSeek / Doubao，可在设置中切换）
      │
      ▼
解析 AI 返回（JSON 格式）
├── 新增一条记录到 ai_analysis 表（不覆盖旧的）
└── 返回给前端展示
```

#### 6.1.2 多模态图片分析流程

```
用户在饮食记录页上传食物照片
      │
      ▼
前端 POST /api/upload/meal-photo（保存图片）
      │
      ▼
前端 POST /api/ai/vision/analyze（发送图片路径）
      │
      ▼
后端读取图片，调用多模态 AI（Doubao Vision 等）
      │
      ▼
返回分析结果：
├── 识别的食物名称
├── 估算热量（kcal）
├── 营养成分概要
      │
      ▼
自动回填到 meal_records.ai_calorie_estimate
```

### 6.3 AI 调用策略

| 策略 | 说明 |
|------|------|
| **文本模型** | DeepSeek-Chat 或 Doubao（在设置页面中自由切换 API URL/Key/模型名） |
| **多模态模型** | Doubao Vision 等支持图片输入的模型（独立配置） |
| **触发方式** | 手动点击按钮触发（避免隐性消耗 token） |
| **频率限制** | **无限制** — 一天内可随时多次触发分析 |
| **存储策略** | 每次分析结果作为新记录存入 `ai_analysis` 表，**不覆盖旧记录** |
| **展示策略** | 前端展示当日所有分析报告（最新在上），形成「分析时间线」 |
| **错误处理** | API 超时/报错时，前端显示友好提示，不影响其他功能 |
| **token 追踪** | 记录每次消耗的 token 数，月底可查看用量 |

### 7.2 各页面功能描述

- **统计卡片区**：当前体重、目标体重、BMI、已减重、今日波动幅度
- **今日体重波动图**：折线图，横轴为时间点，纵轴为体重，每个点标注时段标签
- **多周期趋势图**：曲线图，展示每日晨起体重趋势 + AI 预测线（虚线），支持周期选择器（7天/14天/30天/90天/全程/自定义日期范围）

- **AI 快报卡片**：展示最新 AI 分析的摘要（`weight_status` + `predicted_morning_weight`）

#### ⚖️ 记录体重 (`record.js`)

- **大号体重输入框**：类似秤的 UI，数字键盘输入
- **时段快速选择**：预设按钮（晨起 / 午饭后 / 晚饭前 / 睡前 / 上厕所前后 / 其他）
- **备注输入**：可选文本框
- **今日已记录列表**：时间线展示，每条可编辑/删除
- **一键提交 + 自动保存**：提交后自动更新 `daily_summary`

#### 🍽️ 饮食记录 (`meals.js`)

- **餐次 Tab**：早餐 / 午餐 / 晚餐 / 加餐
- **描述输入**：自由文本，描述吃了什么
- **📷 食物照片上传**：拍照/选择照片上传，点击「AI 分析热量」按钮调用多模态 AI 识别食物并估算热量
- **热量输入**（可选）：手动输入或使用 AI 估算值
- **今日饮食时间线**：展示所有已录入的饮食（含照片缩略图）

#### 🏃 运动记录 (`exercise.js`)

- **运动类型快选**：常见运动按钮（跑步/走路/游泳/力量/瑜伽/骑行）+ 自定义输入
- **时长输入**：分钟
- **强度选择**：低/中/高
- **今日运动列表**

#### 🤖 AI 分析 (`analysis.js`)

- **「开始分析」按钮**：触发 AI 分析（Loading 动画 + 打字机效果展示结果），**可反复点击生成新分析**
- **分析时间线**：当日所有分析报告按时间倒序排列（最新在上），每条显示生成时间
- **关键指标摘要**：预计今日减重、明日晨起体重、热量缺口（取最新一条分析）
- **历史分析列表**：可按日期查看往日的 AI 分析
- **删除功能**：可删除不需要的分析记录

#### ⚙️ 设置 (`settings.js`)

- **基本信息**：身高、目标体重、性别、活动水平
- **AI 文本模型配置**：API Key、URL、模型名称（DeepSeek/Doubao 等可切换）
- **AI 多模态模型配置**：API Key、URL、模型名称（Doubao Vision 等）
- **数据管理**：导出数据、清空数据、备份
